# Seven Card Show Android App Readiness

## Architecture
The application utilizes **Capacitor** as the bridge to bundle the existing static web game into an embedded Android WebView. This creates a fully native Android shell (handling app lifecycle, permissions, and orientation) around the existing web UI, keeping all logic in the current JavaScript game engine.

## Existing Web App Protection
- **Zero Modifications to Web Project:** All game logic, styling, and UI logic in the main repository remain completely untouched.
- The web build continues to function exactly as before for Cloudflare Pages.
- Tests were successfully run (`npm test` and `npm run test:ui`) with zero failures before and after the Android conversion.

## Android Project Structure
A new sibling directory called `android-app/` has been created:
- `android-app/sync.js`: Custom script that intelligently copies `src/`, `public/`, `index.html`, and other web assets into `android-app/www`.
- `android-app/capacitor.config.json`: Configuration for the Capacitor app (App ID: `com.siddarth021.sevencardshow`).
- `android-app/build-aab.bat`: Automation script to sync files, copy them to Android, and trigger the Gradle release build.
- `android-app/android/`: Native Android project generated by Capacitor.

## Technology Choice
**Capacitor** was selected because it wraps existing web applications into native iOS/Android containers seamlessly, requires zero rewriting in Java/Kotlin or React Native, and supports ES modules natively. 

## Game Logic Preservation
Because we are utilizing a WebView pointing directly at the copied assets from the verified web deployment, all game logic remains exactly identical.
- Joker functionality matches the web.
- SHOW logic and penalties remain the same.
- Multi-card dropping and Draw logic is the exact JavaScript code that currently passes the 51 web tests.

## Android UX
To ensure the app feels native:
- **Portrait Lock:** `android:screenOrientation="portrait"` has been added to `AndroidManifest.xml`.
- **Action Bar:** `AppTheme.NoActionBarLaunch` is utilized to ensure there's no visible browser address bar.
- App handles standard touches properly due to Capacitor's internal touch handling.

## Offline Capability
The current game is fully static (HTML, CSS, JS) and has no network dependency. By bundling it via Capacitor, all assets are shipped inside the APK/AAB, making the game **100% playable offline** without requiring a service worker or backend connectivity. 

## Security
- The app requires no external API keys.
- **Permissions:** Capacitor adds standard permissions to the manifest. I preserved only what was essential (Capacitor generally requests INTERNET for its internal local server bridge). No unnecessary permissions (Location, Contacts, etc.) are requested.
- Debug configurations will be disabled when compiling with the `bundleRelease` task.

## Automated Tests
- **Web Tests:** `npm test` and `npm run test:ui` both pass successfully on the root directory.

## Build Instructions
1. Open terminal and navigate to the `android-app` folder:
   `cd android-app`
2. Run the build script:
   `.\build-aab.bat`
*(Note: As discovered during the automated run, you need to have `JAVA_HOME` configured and the Android SDK / Gradle installed on your Windows machine. If you prefer a visual interface, open `android-app/android` inside **Android Studio** and click Build > Build Bundle(s) / APK(s) > Build Bundle(s).)*

## Release Signing
> **CAUTION**
> **DO NOT commit keystore passwords or keys to GitHub.**

To sign the release AAB for Google Play:
1. In Android Studio, go to Build > Generate Signed Bundle / APK.
2. Select Android App Bundle and click Next.
3. Click **Create new...** under the Key store path.
4. Save the `.jks` keystore file locally on your machine (e.g., in a secure offline folder outside of this GitHub repo). 
5. Set strong passwords for the Keystore and the Key.
6. Let Android Studio build the Signed Bundle.
